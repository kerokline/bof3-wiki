# Responsibilities

*Read this if you ask "which code owns this job?" and want the page that explains it.*

Where each part of the game's code lives and what it owns. Use it to answer "where does X live?",
then read the page that owns the mechanism: [overview](index.md), [phases](phases.md),
[loading](loading.md), [saving](saving.md), [disc and files](disc-and-files.md), and the format
layouts in the [editor guide](editor-guide.md).

The rows come from static reading of the program code. No
emulator ran; nothing here was observed at run time.

## How to read it

| Label      | Meaning                                                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `read`     | The name rests on a stated evidence line, and the cited function shows the cited calls, constants and tables.                                                |
| `inferred` | Deduced from callers, callees, the data table that lists the function, address order, shared-body size equality or a file name. Treat as a lead, not a fact. |
| `unknown`  | No evidence for a role. An address name (`func_80158F80`) stays an address name here; ranges are cited by address only.                                      |

A function is `TARGET@0xADDR`; equal addresses in different targets are unrelated. `slus` means
`exe/slus_004_22`. Citations read `Name@address`; the image is `slus` unless given.

Overlays at one address replace one another. `slus` and the EMI overlays share RAM, so an
overlay calls `slus` and `game/00` by address and neither calls back by name. The slot windows are
reserved regions of the `slus` image. That the `boss`, `area030/05`
and `area049/13` images load into them follows from equal addresses and is `inferred`. The
[runtime page](../runtime.md) holds the full load-address list.

### Members that differ

`boss/*`. 12 images add a name to the common four: `Boss_FinishDefeat` (`boss002`, `004`, `017`,
`022`; it banks the enemy's EXP and Zenny and sets the victory bit on the last enemy),
`Boss_EndEntrance` (`boss022`), `Boss_InitEnemy` (`boss037`, `040`, `042`, `049`), `Boss_RunSubStep`
(`boss036`, `052`), `Effect_ShakeScreen` (`boss033`) and `Area_RoundSpriteCoordinate` (`boss055`).
`boss002`, `004`, `008` and `014` carry numbered variants of the hook names (`Boss_EndBattle2` and
so on). `boss055` is the largest (60 functions). All `read` from evidence rows. What each boss
does beyond the hooks: unknown.

`bmagic/*`. 20 images name `BMagic_RunStep`; the others name `Effect_PlayOnce` (`magic008`,
`015`, `020`, `145`, `146`), `Effect_CountDownTimer` (`magic006`, `009`, `039`, `040`, `059`, `126`,
`145`) or `Effect_NextStep` (`magic062`, `082`). The effect each module draws: unknown.

`plchar/*`. 7 images (`plp012`, `015`, `016`, `025`, `026`, `034`, `056`) define the turn shape:
`Char_AdvanceScript@801CEC30`, `Char_SpawnActor@801CEF14` (claims a field record from
`g_ActorSlots`), `Char_StartTurn`, `Char_ProbeFacingCell`, `Char_Turn` (`plp025` has no `Char_Turn`). 11 images
(`plp247`, `257`, `267`, `278`, `27a`, `457`, `467`, `478`, `567`, `578`, `678`) define the walk
shape: `Char_WalkStep@801CE898` ("runs one field-character route step") and `Char_CheckStep`.
`plp349` has no readable name. Which character each module drives: unknown.

`world0N/*`. 38 to 48 areas per world load at `0x801F2C00`. Provable differences:
`world00/area030/04` loads at `0x801D0C00` (237 functions; it calls
`Area_DrawScene@8014BA54` each frame), `world00/area030/05` loads at `0x800F5000` and
`world01/area049/13` at `0x80117000`. 19 areas hold no functions (for example
`world00/area006/13`, `world03/area122/13`). The common names are `Area_Update@801F35F0` ("the
area frame update"), `Area_RunEvent`/`Message_OpenAnswerMenu` (entry `0x801F2C04`),
`Actor_AdvanceWhenPartyNear`, `Actor_SlideScreenX`, `Area_ClearWorkColumn`. `world04` has the most
named functions (85). Area script content: unknown.
